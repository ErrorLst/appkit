# appkit-config 提问清单参考答案（面试官用）

> **面试官用，不要发给候选人。** 候选人看的是 `appkit-config/QUESTIONS.md`（Q1 ~ Q8，编号一一对应）。
> 每问都只考一个点，所以"要点"也就一两句；判断标准是**能立刻给出这一句**，而不是长篇大论。
> 标"实测"的结论都在这份代码上真跑过；括号里是源码位置。

## Q1 换行符：只认 '\n'

**问**（`src/config.cpp:29`，相关 `:14`）：Linux / Windows 的换行？CRLF 多出的字符谁去掉？BOM 会怎样？

**要点**
- LF = `'\n'`（0x0A）；CRLF = `'\r\n'`（0x0D 0x0A）。
- CRLF 每行末尾多出的 `'\r'` 由 `trim` 的空白集合 `" \t\r\v\f"` 去掉。实测 `"name = svcd\r\n"` → `get("", "name") == "svcd"`；`tests/data/parse_basic.ini` 第 3 行就是 CRLF。
- BOM：`EF BB BF` 粘在第一个键名上 ⇒ 实测 `size() == 1` 但 `get("", "a")` 查不到（静默）。README 把编码判给了调用方，所以应由读文件的一方剥掉。

## Q2 值两端的空白被裁掉了

**问**（`src/config.cpp:51`）：`port = 8080   ` 会解析成什么？必须保留空格的值怎么办？

**要点**
- 两端都裁：实测 `"port = 8080   "` → `"8080"`，`"port =    8080"` → `"8080"`。
- 需要保留首尾空格的用户**没有表达方式**（无引号、无转义），只能改字段或换编码 ⇒ 实现悄悄改动了数据。要支持就得加引号，并连带定义引号内 `#` / `;` / `=` 是否还有特殊含义、转义规则、未闭合引号怎么报错。
- 顺带（实测）：行内 `#` 不算注释（`"pwd = ab#cd"` → `"ab#cd"`），值里的 `=` 不会被切坏（`"url = a=b=c"` → `"a=b=c"`）。

## Q3 这行为什么不能省

**问**（`src/config.cpp:15-20`、`:30`）：删掉 `if` 会怎样？另一处的 `end` 也可能是 `npos`，为什么不用判断、也不会抛异常？

**要点**
- 全空白/空串时 `first == last == npos`，所以 `last - first + 1` 就是 `0 + 1 = 1`（`npos` 是 `size_t` 最大值，`npos - npos` 得 0，不会变负）；于是 `substr(npos, 1)` 因 `pos > size()` 抛 `std::out_of_range`（异常，不是 UB）⇒ 那三行必须留。**注意这里跟"回绕"无关**，抛出是因为 `pos` 越界。
- 另一处：`npos` 按"找不到 / -1"理解时，`end - begin` 本该是负数，但无符号整数没有负数，结果按 `2^64` 取模（这就是"回绕"）得到 `SIZE_MAX - begin`——一个极大的 `count`。而 `substr(pos, count)` 在 `count` 超过剩余长度时会截到末尾、不抛 ⇒ 所以不判断也正确，但意图不明显，值得显式写出来或加注释。

## Q4 循环边界

**问**（`src/config.cpp:28-30`、`:61-64`）：`begin == size()` 算越界吗？空文本会失败吗？`<` 和 `<=` 有区别吗？

**要点**
- **不越界**：`substr(pos, count)` 只要求 `pos <= size()`（`pos == size()` 返回空视图，`pos > size()` 才抛 `out_of_range`）；`find(ch, pos)` 在 `pos >= size()` 时返回 `npos`——都是标准规定的结果，不是 UB。实测 `substr(size()).size() == 0`、`find('\n', size()) == npos`。真正越界的是元素访问（`text[size()]`、`operator[]`、解引用迭代器），这段代码没做元素访问。
- 空文本不会失败（实测 `size() == 0`）：走一轮、空行被跳过、`end == npos` 退出，得到一个空 `Config`。退出靠 `end == npos` 的 `break`；`begin = end + 1` 每轮至少 +1 ⇒ 不会死循环。
- **`<` 和 `<=` 在这里完全等价**（实测：把 `<=` 改成 `<` 后所有用例输出逐字节相同）。因为 `end == npos` 已经先 `break`；`begin == size()` 那一轮只在"文本以换行结尾"时才会走到，而那轮的 `line` 必然是空串、被跳过。⇒ 这个 `<=` 属于防御性写法；"`<=` 是为了处理末尾没有换行的最后一行"是常见但**错误**的答案——那一行是在 `begin < size` 的正常一轮里解析完、再靠 `break` 退出的。

## Q5 全表线性扫描

**问**（`src/config.cpp:53-54`，`get` 的查找在 `:70`）：复杂度是多少？这个开销需要处理吗？

**要点**
- 每行都要在 `m_entries` 上线性扫 ⇒ 解析 n 行是 O(n²) 次比较（每次还含字符串比较）；`get` / `has` 每次 O(n)。
- 量级：n=100 → 1e4；n=1e3 → 1e6；n=1e4 → 1e8。配置通常几十~几百行、只在启动期解析一次 ⇒ **不需要**处理；能给出"按数量级判断"就是好答案，比背"应该上哈希表"重要。（真到了那个量级再谈索引/容器，属于另一个话题。）

## Q6 所有权边界

**问**（`include/appkit/config.h:27-32`、`:39-40`、`:49-50`）：`Entry` 为什么必须持有 `std::string`？拷贝后视图指向谁？`expand` 为什么不能借视图？

**要点**
- 入参 `string_view` 只是借用，而 `Config` 常活得比它久（典型：读文件到临时 buffer → parse → 丢 buffer）⇒ 必须深拷贝；存视图会让 `get` 直接返回悬垂视图（偶发崩溃，最难查）。
- 拷贝后视图仍指向**原来那个对象**的字符串：原对象还活着就没事，原对象销毁、或被放进 `vector` 后扩容/搬迁，就悬垂。
- `expand` 的结果是多个条目值拼出来的新内容，不存在于任何 `Entry` 里 ⇒ 只能新造 `std::string`（这也是它比 `get` 贵、并且没有 `noexcept` 的原因）。

## Q7 错误模型

**问**（`include/appkit/config.h:36`，实现 `src/config.cpp:23-67`）：为什么不用异常？"一次报出所有坏行"能满足吗？`std::expected` 能解决吗？

**要点**
- 调用方是启动期加载器：拿到错误要写日志、再决定继续还是退出（应用层策略）。抛异常等于把"必须处理"强加给所有调用方（本项目选择不抛），而失败路径本来就需要一个可传阅的错误对象。
- 不能满足：现在是"遇到第一个错就 `return nullopt`、只带一条诊断"。要改成"记录诊断 + 继续扫描"（结果里带 `vector<ConfigError>`，或接受诊断 sink），并先定好恢复语义（坏行跳过会不会让后续键错位）。
- `std::expected` 只把"值/错误"合成一个类型，错误仍是**一个**对象 ⇒ 不解决，除非 E 本身就是多错误容器。

## Q8 不可变快照与线程安全

**问**（`include/appkit/config.h:39-50`、`:65-66`）：只读并发为什么不用锁？加 `mutable` 缓存会怎样？

**要点**
- 安全，不需要锁：解析完成后 `m_entries` 不再变、查询都是 `const`、没有 `mutable` 也没有惰性初始化 ⇒ 多线程只读不构成数据竞争。
- 加 `mutable` 缓存就把读操作变成写内存 ⇒ 需要锁/原子，否则是数据竞争（UB）。`const` 只保证"不改对外可见状态"，不保证"不写内存" ⇒ const ≠ 线程安全。
